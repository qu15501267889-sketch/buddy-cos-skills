# 教学式回答 与 聊天记录整理

> SKILL.md §8 的展开。他问技术原理、或要他整理聊天记录时，照这里的格式走。

## 一、技术问题：先大白话，再拆解

他问采样器、调度器、cfg、denoise、steps、resolution 这类参数问题时，**一律两段式**：

1. **第一句必须是大白话点本质** —— 用生活比喻，不出现术语。
2. 第二段才拆原理、讲影响、落到他这台机器（RTX 4060Ti 8G）上的实际表现。

**禁止**：一上来甩术语表、先讲定义再讲用途、给一串参数推荐表却不解释为什么。

### 已用过的比喻（可复用，也可换新的）

| 参数 | 大白话本质 |
|---|---|
| 采样器 sampler | **走路的步法**——每一步往哪个方向迈、迈多大，决定收敛得快不快、会不会绕圈 |
| 调度器 scheduler | **路面的坡度**——决定每一步跨多大距离，是匀速走还是先大后小 |
| cfg（无分类器引导） | **听不听话的力度**。数值高 = 死磕提示词但容易僵硬失真；数值低 = 自由发挥但可能不听指挥。**本机跑 Qwen-Image 一律 1.0，因为它不吃负面提示词** |
| denoise（重绘幅度） | **改多少**。1.0 = 整张重画；0.5 = 保留一半原图。图生图要保脸保身材，这个值基本贴 1.0 但靠「保持不变」段锁人 |
| steps（步数） | **打磨几遍**。不是越多越好——过了某个点就是原地空转，只是更慢 |
| resolution | **画布多大**。不是越大越清晰，超过模型原生训练尺寸反而会裂 |

### 讲完之后

给一句**落地结论**：他这台机器上该注意什么（显存、耗时、哪个档位值得等）。

## 二、聊天记录整理格式

他要「整理聊天记录 / 把这段对话整理出来」时，固定三件套：

```
<教学文案 / 正文内容>

以下是完整聊天记录：

左：……
右：……
左：……
右：……
```

### 硬规则

- **纯对话流**：一行一句，`左：` / `右：` 区分说话人，冒号后直接接内容。
- **无页码标记**（不写「第 1 页 / P1」）。
- **无时间戳标记**（不写「[15:16]」）。
- **无小标题、无分隔线、无序号**——中间不许插「（以下为第二部分）」这类东西。
- **不自动去重**：重复的内容原样保留，他要自己去重，不要替他判断哪句是废话。
- **不润色、不补全、不省略**：他说的原话照抄，包括错字和口语。铁律六。

### 正文放在哪

教学文案 / 说明部分放最前面，跟聊天记录之间只隔一行空行 + 「以下是完整聊天记录：」这一句，不要加分割线或标题。

## 三、他问「还记得这个吗」

不是教学题，是**记忆抽查**。

- 去 `references/` 找对应的 `*-case-*.md`（大乔 / 妲己 / 甘雨 / 云缨 / 少司缘）。
- 找到就**逐字贴出该单提示词全文**，不要概括成「那单大概是什么什么风格」。
- 找不到就直说「这单的全文我没存到 references 里，只记得 XX」，然后问他要不要补档。**不许编**。
